# 统计报告经验

只保留实际反馈和核查中形成、可跨任务使用的方法。各项目的数字、字段定义和业务决定以当前资料为准。

## 让数字回答问题

- 简要不是省略关键依据：每个主题先说明涉及多少，再解释其中缺失、异常或差异有多少，以及对实际问题有什么影响。整体数量已就近说明时，表格单元格可以只写“缺多少”。
- 按一个业务问题组织关联信息。比如分析人员来校日期，应同时看人员类别、接口是否提供日期、科研系统是否保存，以及实际使用该日期的判断；不要把相关信息拆散后让读者自行拼接。
- 对缺失或异常数据，只有总数通常不够。可以按来源、人员类型、当前状态等有业务意义的维度分层；发现异常集中在哪类数据后，再判断优先处理范围。

## 避免混淆数量和覆盖

- 对比数据先分清匹配、未匹配及重复或歧义；在每个字段中先给相关范围的总数，再给该范围内的缺失或不同数量。接口全部能找到学号，不代表字段全部相同或关联关系唯一。
- 对重复档案分别呈现原始记录数和按业务对象归并后的数量。例如同一学号有两条记录，一条证件号为空、另一条有值，补齐空记录会改善记录完整性，但不等于新增一名可识别学生。
- 键值标准化、大小写和数据库排序规则可能把不同标识合并；区分确属重复和标识相近但实际上不同的对象。同一人不同学习或任职阶段也不等于应删除的重复档案。
- 可补数量、补充后剩余数量和实际已更新数量是不同概念。写清计算范围，以及数据来自接口、同组已有记录还是有效证件号解析；不要把只修复重复行描述为提升独立人员覆盖。

## 查明来源、原因与时点

- 接口名称、来源类别和字段值可能并不等价。核查两边对应字段的实际分布，并结合新增、更新和字段转换代码，避免将默认赋值解释为已确认的真实身份。
- 科研或业务系统有值、接口为空时，既要统计这部分，也要考虑历史保留和同步不覆盖空值等有证据的解释；没有历史记录时，不推断原始来源。
- 当前状态、预计结束日期和实际历史状态是不同信息。涉及某日身份或资格时，说明已有的起始时间、实际结束时间和状态变化记录能否覆盖该时点；不能从当前状态反推历史。
- 读取状态字典与同步转换规则，区分名称不同但可建立映射、现有代码已经自动转换、以及没有对应值三种情况。可人工映射不等于当前同步已实现。
