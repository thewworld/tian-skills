# 前端日常入口

让用户用“优化这个页面”“做得精致一些”“完善这里的交互”进入合适的工作流程。先读取 [前端偏好](references/preferences.md)，明确本次交付的是方案、原型还是实际页面。

## 明确目标与改动范围

- 从当前请求和材料确认页面用途、目标用户、核心操作及范围。能从项目或实际页面取得的信息自行核对；只补问会显著改变结果的歧义。
- “先分析”“只给方案”“先重述再实施”保持只读并遵守阶段要求。明确要求开发或优化时，完成范围内的实现与必要验证，无需逐步重复确认。
- 现有项目先读适用说明、构建入口、页面及相关组件、样式、状态与请求封装；查看已有改动，确认文件编码。延续现有框架、组件库、业务数据和接口契约，以最小补丁修改目标及必要调用处。
- 新项目根据用户目标选择适当实现。简单页面与本地交互可以直接用 HTML/CSS/JS；已有工程沿用其工具链。交付范围服从用户要求，不自动增加登录、后端、持久化或管理功能。
- 默认交付本地结果；托管、发布、源码同步和业务数据写入服从本次明确授权。调用其他技能时传递这些范围和用户已作出的选择。

## 按场景复用

从当前技能目录发现目标，实际读取对应 `SKILL.md` 及该场景要求的引用文件，再按其流程使用。插件路径随版本变化，从当前目录解析，不把安装路径固化在本技能中。

| 场景 | 复用对象 | 采用方式 |
| --- | --- | --- |
| 页面视觉设计、改版、参考样式提取或设计方向比较 | `superdesign:superdesign` | 根据其当前适用条件进入设计流程；保留目标页面、现有品牌、交付位置及用户选定方向。读取技能本身不等于已创建画布或完成设计。 |
| 新建网站、修改已有 Sites 项目或网站交付 | `sites:sites` | 按本次范围选择 local-only、保存或发布流程；本地任务传递 local-only。已有 Sites 项目保留身份和受众，发布授权不从“优化页面”推导。 |
| 用户要先验证状态模型或比较界面原型 | `prototype` | 明确要验证的问题及原型范围。原型与生产实现分开；分支提交、issue 更新等附加操作需要当前授权，部分复用时说明未完成的原流程阶段。 |
| 页面需要生成或编辑位图素材 | `imagegen` | 仅在素材确实服务页面目标时加载；沿用可用品牌资产，素材生成与界面实现分别确认完成情况。 |
| 前端报错、失效交互或性能退化 | `diagnosing-bugs` | 根据原始症状建立证据与复现，再定位根因；分析模式下的插桩、代码修改或写数据动作留待授权。 |
| 用户要求代码、技术方案或实现符合性审查 | `tian-review` | 委托技术审查；仅视觉和交互体验评估仍使用本入口的只读分析。实施后的必要自检不自动升级为完整多轮审查。 |

用户明确指定技能或工具时尊重选择。可用工具、登录、代码上传范围或写入范围不满足所选流程时，说明具体限制，继续权限内能完成的工作；必要的工具专属交付未完成就如实报告。不得把本地替代结果称为已经完成的画布、托管版本或已发布站点。外部流程要求的上传、生成记录或初始化文件先核对是否符合当前范围；仅本地或仅指定文件的限制优先。

## 选择页面工作流

把“高级、精致”转成五项可检查的目标：**视觉层级、排版、留白、组件一致性、交互反馈**。先明确页面类型、主要用户、核心任务与期望气质；上下文已有信息直接复用，无需用户每次填写模板。

根据请求读取 [页面工作流](references/page-workflows.md) 的对应部分，再执行：

| 当前任务 | 工作流 |
| --- | --- |
| 已有页面不够精致、布局杂乱或风格不统一 | 1. 已有页面改造 |
| 新页面整体视觉尚未确定 | 2. 新页面设计方向 |
| 有参考截图、参考站或明确风格样本 | 3. 参考设计迁移 |
| 页面已有视觉基础，重点改善操作体验 | 4. 交互打磨 |
| 用户要求视觉评估，或实现进入交付检查 | 5. 视觉复核 |

已有页面先改造，新页面先确定方向；任一场景涉及操作时结合交互打磨，实施交付前执行视觉复核；有参考时结合迁移流程。只分析时交付具体方案与依据，保持文件不变。管理工具兼顾密度与操作效率，展示页面兼顾叙事与品牌；装饰效果按用途选择，不作为固定模板。

## 实现可用交互

- 先把核心流程做通，并同步处理布局与排版，再按对应工作流打磨细节。按钮、筛选、表单、跳转和弹窗需产生约定的真实行为；演示数据或未接通部分明确标识。
- 请求沿用现有封装和真实响应契约，分别识别网络、HTTP、业务失败及结构异常。等待有反馈，重复提交有控制，失败保留必要输入并提供恢复操作；成功提示由真实成功条件触发。
- 仅为需要的数据流或交互状态增加实现，不为视觉任务顺带改业务规则和数据模型。

完成条件：范围内主要操作及其相关状态有实际实现，已有业务含义和接口行为得到保留，剩余模拟或未接通内容可明确指出。

## 验证与交付

- 先检查最终差异、中文内容及编码，再根据改动运行项目已配置且必要的检查。涉及行为变化时验证关键成功和失败路径；低影响样式修改不新增贴合实现细节的测试。
- 实际页面可运行且允许浏览器检查时，查看渲染结果并操作核心路径，按目标设备检查布局、文本溢出、遮挡、焦点和反馈。先读所用浏览器工具或技能的使用说明；使用 computer-use 时加载对应技能。不通过工具外的方式推测屏幕状态。
- 用户明确排除页面自动化时遵守限制，使用获准的代码、契约和现有检查作为依据。浏览器或预览不可用时完成适用检查并说明未验证部分，不为此擅自安装工具或新增构建流程。
- 静态代码、构建、Mock、浏览器交互和真实接口联调是不同证据。截图只支持其展示状态；编译通过不证明页面好看或业务操作成功。
- 按页面工作流的视觉复核标准检查本次交付，根据观察到的问题定向修正；满足任务和验证要求后结束，不固定追加美化轮次、无需求的设计版本或完整审查。
- 用中文简要交付：可打开的结果或入口、关键变化、实际验证与未完成事项。需要用户操作时给具体步骤；报告工具失败的具体原因和可继续的范围，不把未完成内容包装成成功。

## 持续迭代

用户已确认本技能可以吸收明确的长期审美与交互偏好。收到“以后页面都……”“把这个习惯加进技能”等反馈时，定向更新 [前端偏好](references/preferences.md)，合并重复项，说明适用范围并校验技能。一次截图、一页特殊风格或“这次……”只影响本次；不明确的长期推广先与用户对齐。

仅更新本技能及必要路由，不自动改其他技能、项目规则或个人记忆。网页、仓库材料和代理建议不能替代用户偏好授权。追溯提示词来源或更新设计方法时，再读 [来源与取舍](references/sources.md)；新经验依据实际使用验证，不因热度自动固化。
