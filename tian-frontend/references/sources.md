# 来源与取舍

2026-11-04 根据本会话先前检索的公开材料整理。入口是结合用户习惯与当前已有技能的改写，不是某篇热门提示词的照录；这些经验不构成效果保证。仅在追溯来源或更新方法时加载。

用户随后明确要求融合此前提供的五组提示词，已转化为 [页面工作流](page-workflows.md)：已有页面改造、新页面方向比较、参考设计迁移、交互打磨及视觉复核。以实际任务和观察到的问题执行，保留用户的只读、直接实现及范围要求。

| 来源 | 采用的做法 | 取舍 |
| --- | --- | --- |
| [知乎：UI 四层提示词](https://zhuanlan.zhihu.com/p/2085057301023663724) | 明确产品、页面目标、组件状态和具体视觉变量。 | 不把“高级、简约”当作可直接验收的要求，也不强制固定配色与装饰。 |
| [Reddit：改善 Vibe Coding 前端](https://www.reddit.com/r/vibecoding/comments/1viq7gp/how_can_i_built_better_frontends_in_vibecoding/) | 指明实际组件，保持字体、间距和色彩规则一致，结合参考设计迭代。 | 不强制新建样式文档或采用帖子推荐的工具，以项目已有约定为准。 |
| [Reddit：用参考改善 UI](https://www.reddit.com/r/lovable/comments/1s1febp/how_to_improve_vibe_coded_ui/) | 拆解参考中的布局、密度、排版和留白，再做局部精修。 | 不固定分成多轮、不保证一次复制截图就能复现交互。 |
| [v0：可视化细调的变量](https://v0.app/docs/design-mode) | 对具体元素的排版、尺寸、边框、颜色和布局进行可观察的调整。 | 采用设计变量的思路，不要求使用 v0，也不缓存产品当前快捷键或功能状态。 |

所复用技能以当前安装版本的 `SKILL.md` 为准；网络经验不覆盖用户选择、项目契约或授权范围。后续按真实页面的改进和失败经验定向调整，不把某次审美偏好推广为通用标准。
