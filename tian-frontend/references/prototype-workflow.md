# 业务原型设计与保真落地工作流

适用于制作业务详情页/工作台高保真交互原型，以及将已确认的原型精准落入正式项目代码中。核心目标是：**首屏主次分明、零重复堆叠、契约真实可信、交互克制直观，并在工程落地时不走样**。

---

## 一、设计前：真实契约锚定与第一主语

已有业务代码、接口或规则文档时，先核对真实上下文，**严禁仅凭界面模板脑补业务**：

- **口径与字段溯源**：先核实触发条件、判定门槛、分组计算粒度、各角色管辖/可见权限及真实数据源名称。**严禁虚构不存在的字段名、审批节点或外部数据源**；未接通或纯粹用于演示的字段必须显式注明或先与用户确认。
- **确定页面“第一主语”**：按业务事件的实际责任主体确定视觉起点与主从次序，而不是按数据表顺序平铺或默认左人右事均等切分（例如在外层采用“左事实 + 右操作”双栏时，左侧内部不再对半劈成 50/50 并排键值表，防止视线三列折返）。
- **业务语言去黑话**：面向一线业务用户的界面，隐藏数据库主键、快照标志、分组键（Group Key）、版本号标签等技术内部术语，转为自然、中性、易懂的业务表达。
- **演示数据账实自洽**：原型内各区域汇总数与明细清单之和必须实时一致；涉及多视角或状态流转时，切换角色、状态或边界情形（缺失值/空值、临界值、退回再提、多条关联）需联动更新对应数据范围与日志历程。

## 二、信息分层与减法铁律（Single Source of Truth）

1. **三层单向信息流**：
   - **一级核心（首屏定性）**：问题类别/级别 + 核心主体 + 关键量化结论 + 简短理由与对照标准（标准条件与下方证据严格同序映射）。不把次要档案和长段法条展开铺满首屏。
   - **二级事实（核查明细）**：只展示核实结论必需的字段与表格；少数独立事实优先用单层紧凑规格条或横向对照条，多条目清单默认折叠按需展开（未明确选定某一条目前，顶部主卡呈现汇总或待选态，**严禁默认回退填充首条明细伪装单一主体**）。
   - **三级档案（按需探查）**：主体基础档案、长文本全文、多源明细拆解与历史补充记录，收入弹窗、行内折叠开关或原生完整悬停，保持日常首屏通透留白（避免高密度满屏堆砌）。
2. **反重复、防碰撞与去冗余自检**：
   - **单一事实源**：同一字段（如姓名、总额、编号、代码、来源）不在主卡、副标题、明细区与弹窗之间反复复读；详情弹窗只放主体客观档案，不再抄录主界面的结论指标或流转状态。
   - **拒绝硬凑与套娃**：不为布局对称强行塞入第二个大指标，不在卡片内部再叠多层有框底盒（能用间距和极细分割线区分的，不用卡片套卡片）；不在标题和表格之间硬塞补充副行。
   - **长名称与边界容错**：主标题允许自然折行；表格或窄槽中的长项目名、长机构名设置清晰截断（如默认 2 行）并保留完整查看路径（`title` 或展开明细），同时校验两端对齐文案在长名称下是否会挤压撞车。
   - **常态从简、例外显式**：默认常规行不贴状态胶囊（只标出例外行）；非强警示的辅助属性优先用中点分隔灰字替代矩形色块标签；逻辑连接词（如“且 / 或”）保持常规字重，不加粗抢戏；不写“说明书式”的冗长解释句。

## 三、交互尺度与视觉一致

- **点击落点同一套直觉原则（“信息在哪，点击去哪”）**：
  - 同页下方已有对应核查区块 → 点击后平滑滚动至目标区块（预留安全顶距）并伴随短暂微光高亮；
  - 同页下方无独立区块 → 点击后就地弹出轻遮罩信息名片（实体不透明、高度自适应、支持按钮/遮罩/键盘常用退出键关闭）；
  - 跳转外部系统 → 使用统一纯净的外链微图标或极简短链，全页收敛同功能入口数量，不四处重复摆放。
- **可点击线索的克制平衡**：
  - 避免把可点击行为完全藏在纯 Hover 变色里（触屏和静态截屏下无法发现）；
  - 也避免把长标题整片改成刺眼超链接蓝或堆砌琐碎装饰小贴图抢夺核心警示焦点；
  - 优先保留正文与大标题稳重字体，辅以一致轻量线索（如柔和细虚线底边或专职微图标），Hover 时再叠加主色微底与轻量不遮挡提示气泡（动词前置、避让上方核心徽标、随系统主色）。
- **视觉语义与全局锚点**：
  - 状态风险色（红/黄/蓝等）、品牌操作主色与时限紧急度（文字/图标）各司其职，避免同色多义引发误判；在确保对比度的前提下保持警示色清晰可辨，防止过度压暗发灰/发棕。
  - 全局高频状态锚点（如剩余限期倒计时、核心操作区位置）在不同视角与规则分支中固定在同一位置，不随分支随意搬家。

## 四、原型工程与决策推敲习惯

- **先给明确唯一首选方案**：面对多方案取舍或样式争议时，直接结合真实业务与渲染成本给出单一首选判断和理由，不在相互矛盾的方案间来回摇摆。
- **局部试点验证再同构推广**：涉及整体视觉或交互体系改造时，先选 1 个典型页面或单个分支完成调整并查看实际渲染，经确认后再同步推广；推广时抽取共享组件或公共渲染函数统一驱动（如同一套主体点击、标准条、弹窗结构），并逐支核对清单防止“改了几个漏掉其余分支”。
- **保护已确认逻辑基线**：后续迭代或简化重构时，必须严格保护用户在前序轮次中已经明确确认过的交互习惯与规则逻辑（例如已定好的定位动作、高亮规范），不得顺手改丢或悄然回退。
- **独立可分享原型封装**：若交付物为静态可交互原型（如单文件 HTML），确保 CSS/JS/图标/模拟数据全量内联、无外部构建或网络依赖；顶部配置轻量切换控制条（切场景分支、角色视角、边界情形）并支持一键切入**纯净预览模式**（隐藏控制条）以便评审截屏。

## 五、「定稿原型 → 正式代码」保真落地准则

将确认后的原型同步到正式工程时，极易发生**“拿旧代码套原型壳子导致结构走样”**或**“向首屏私自回塞额外说明”**，必须遵循以下约束：

1. **按原型骨架重写，禁止旧架构套壳**：先逐块核对原型与现有代码结构差异。视觉布局与卡片粒度直接以定稿原型骨架为准重写（如原型用单层规格条与横向证据条，就不得图省事沿用旧的多层大卡片），同步校对 CSS 类名是否准确接入，防止无效类名退化样式。
2. **明确“原型精简 vs 生产复杂性”的收放边界**：
   - 当真实业务比原型多出历史多版本口径、数据缺失/未公示、多条目汇聚或只读权限等场景时，先评估“100% 照搬裁剪”与“骨架对齐 + 折叠收纳”对业务闭环与用户体验的影响，确认取舍后再编码。
   - 确立策略：**首屏可视化外观与骨架 100% 忠于原型，扩展核查依据全部收纳至行内例外短注或按需展开的二级抽屉/弹窗**，不得摊平撑爆首屏。
3. **落地防偏检查清单（对照原型逐块查）**：
   - **不私自加料**：原型各卡片角落、头部或标题行留空处，不自行塞入内部记录编号、计算时间戳、口径版本标签、“仅作展示”等装饰语或说教式解释文案；
   - **不漏核心微交互**：原型设计的外链微按钮、标准条件与证据双向联动、实体弹窗及滚动高亮，必须逐项落实；
   - **不用大块灰色说明顶替只读工作台**：当当前用户无权办理或处于只读查看态时，优先保留与原型一致的表单外观骨架（如禁用输入与操作按钮配轻量只读提示），不用大片灰色说教盒替代操作区结构；
   - **不波及未授权分支与破坏边界**：新引入的原型级样式必须限定在局部作用域或目标规则范围内，严禁无意改坏其他分支或破坏多条目未选定安全态。
4. **交付验收铁律**：不能用 `tsc`/单元测试/样式编译通过代替原型还原验收。必须在真实浏览器渲染画面或逐区块清单上，对照原型图**逐个区块、逐个角落、逐项交互**对比确认外观与行为一致后再交付；不看实际渲染就断定效果往往隐藏布局错位。
