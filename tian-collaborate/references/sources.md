# 来源与取舍

本技能结合本会话已检索的公开经验与用户确认的协作目标整理，不是任何原帖原文，也不是效果保证。仅在追溯出处、改进方法时读取。

| 来源 | 采用的部分 | 取舍 |
| --- | --- | --- |
| [中文分享：把任务做深入](https://www.sina.cn/news/detail/5354050711196748.html) | 检查必要的专家工作、原始资料、具体方法及独立验证依据。 | 聚焦当前目标，不由“深入”推导更多功能或更大范围。 |
| [Reddit：证据、假设与替代解释](https://www.reddit.com/r/PromptEngineering/comments/1m8bs30/i_used_a_neuroscientists_critical_thinking_model/) | 从证据、关键前提、其他视角及后果检查判断。 | 不强制固定步骤、固定反对或长篇分析。 |
| [Reddit：澄清问题的日常用法](https://www.reddit.com/r/PromptEngineering/comments/1ve8wl1/i_stopped_giving_ai_perfect_instructions_i/) | 在复杂任务前明确真实需求及未经检查的假设。 | 不用“直到有 95% 把握”充当提问停止条件，简单明确任务直接完成。 |
| [Anthropic：智能体结果评估](https://www.anthropic.com/research/demystifying-evals-for-ai-agents) | 根据任务选择可观察结果、程序检查或人工判断，区分执行记录与实际结果。 | 不把自评分当作准确率，不为普通任务建立完整评测系统。 |
| [Self-Refine](https://arxiv.org/abs/2303.17651) 与 [推理自我纠错的局限](https://arxiv.org/abs/2310.01798) | 将检查和修订用于改进交付，同时保留任务、模型及外部反馈的限制。 | 不承诺反省必然纠错，不固定追加反思轮次。 |

本地专业技能以当前版本为准；来源启发不替代用户授权。按真实使用中的具体失败定向改进，避免用热度代替验证或将个人案例推广为普遍结论。
